## О проекте
Система мониторинга P2P курсов криптовалют. Биржи: Binance, Bybit. Криптовалюты: USDT, USDC. Фиат: UAH. Цель — собирать историю цен, потом использовать для аналитики, алертов, AI-агента.

## Технический стек
- Python 3.13
- SQLAlchemy 2.0 (Mapped[]/mapped_column через DeclarativeBase, синхронный режим)
- httpx (синхронный, для HTTP-запросов)
- APScheduler (BlockingScheduler для расписания)
- pydantic-settings (для конфигов)
- rich (для логов и таблиц в терминале)
- SQLite сейчас, переезд на PostgreSQL потом (код должен быть переносим)

## Окружение
- Windows + PowerShell
- venv в `.\venv\` (активация: `.\venv\Scripts\Activate.ps1`)
- PYTHONUTF8=1 для корректной кириллицы (уже в .env, в settings.py есть extra="ignore")
- Все файлы в UTF-8

## Структура проекта
- `core/` — общая инфраструктура (database, exchanges, utils)
- `modules/` — независимые модули (tracker, потом spread_scanner, alerts, ai_agent)
- `config/` — настройки (settings.py, .env)
- `data/` — БД (p2p.db)
- `logs/` — логи (general + errors.log)
- `scripts/` — точки входа (init_db.py, run_tracker.py)
- `main.py` — заглушка проекта в корне

## Конвенции кода
- SQLAlchemy 2.0 синтаксис: только Mapped[] и mapped_column(), никакого declarative_base() из ext
- Все datetime в UTC через datetime.now(UTC)
- Без async — везде синхронный код
- Логгеры через core.utils.logger.get_logger(name)
- Ошибки сборщика — в logs/errors.log с traceback
- Контекстные менеджеры (with-блоки) для клиентов бирж и сессий БД
- Все клиенты бирж имеют единый интерфейс: метод fetch_orders(asset, fiat, trade_type, rows, page)
- trade_type "BUY"/"SELL" — единая семантика (BUY = мы покупаем крипту у мейкера)

## Запуск команд в Windows/PowerShell
- Использовать `.\venv\Scripts\python.exe` явно (не полагаться на python в PATH)
- Для скриптов из подпапок — запуск через `python -m path.to.module` (а не напрямую путём к файлу), чтобы импорты работали
- Для UTF-8 в консоли — устанавливать `$env:PYTHONUTF8=1` перед запуском
